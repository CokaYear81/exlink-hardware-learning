## 本章起点

看懂一部分原理图之后，下一步是把抽象的器件位号变成真实焊点。对我来说，焊接最初像一种完全依赖手感的技能：温度应该是多少、锡放多少、芯片怎样才算对齐，这些都不是只看文字就能掌握的。

真正开始以后，我发现焊接也可以像调试程序一样拆分：控制变量、缩小范围、每完成一个模块就立即验证，而不是把整块板全部焊完后再面对一个巨大的未知问题。

## 工具第一次有了具体用途

| 工具或材料 | 我在项目中逐渐理解的用途 |
| --- | --- |
| 电烙铁 | 固定元件、补焊、拖焊和局部返修 |
| 热风枪 | 让密集引脚或底部焊盘整体受热并完成回流 |
| 锡膏与焊锡丝 | 提供焊料，但锡量并不是越多越可靠 |
| 助焊剂 | 改善润湿，让焊锡更容易回到焊盘和引脚上 |
| 镊子与放大设备 | 对齐小元件、检查连锡、虚焊和方向 |
| 万用表 | 在上电前查短路，上电后确认各电源轨和信号状态 |
| 酒精与棉签 | 清理残留，让真正的焊点状态能够被看清 |

## 小封装带来的现实感

0603、0402、Type-C 接口和 QFN 芯片让我第一次感受到，原理图上同样大小的符号，在实物上可能有完全不同的焊接难度。

这里值得记录的不是“我掌握了某种完美手法”，而是手感怎样逐渐形成：如何减少锡量、怎样判断元件是否平贴、什么时候应该停下来清洗和观察，以及返修时为什么需要耐心。

## 我采用的阶段划分

我没有一次性焊完整块板，而是按照能够独立验证的功能逐步推进：

```text
功率板电源
  -> ESP32-S3 与 USB 最小系统
  -> 屏幕和接口电路
  -> 信号板电源与主控
  -> 剩余接口和整板联调
```

## “测一下”开始成为习惯

以前遇到程序错误，我会看日志、打断点；焊接以后，我增加了另一套观察方法：断电测通断和电阻，上电测电压，观察器件是否异常发热，再结合电脑枚举和串口信息判断问题在哪一层。

我逐渐理解了为什么每焊完一小部分就要检查。电源阶段的错误可能让后面的所有现象失去意义，而一个不起眼的连锡或虚焊，也可能在软件层表现成完全不同的报错。

## 阶段小结

焊接让我第一次直接面对“代码之外的误差”：手工操作、器件公差、接触状态和测量方式都会影响结果。我学到的最重要原则不是追求一次成功，而是让每一步都能检查、能解释、能回退。
